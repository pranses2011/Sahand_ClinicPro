## ۱. 📌 چه چیزی عوض شد و چرا؟

تا نسخهٔ `v2.12.0`، **کلید امضای JWT به‌صورت متن آشکار در `appsettings.json` داخل مخزن گیت** بود
(ایراد BUG-01 سند DEFECTS مالک). هر کسی که به مخزن یا بستهٔ نصبی دسترسی داشت می‌توانست:

1. با همان کلید، **توکن جعلی با نقش ادمین** بسازد؛
2. همهٔ درخواست‌های احراز هویت سرور را به‌عنوان کاربر معتبر قبول کند.

| تغییر | توضیح |
|:---|:---|
| `appsettings.json` | مقدار `Jwt:SecretKey` حالا **خالی** است — کلید از فایل حذف شد |
| گارد راه‌اندازی | سرور در محیط **تولید** بدون کلیدِ قوی بالا نمی‌آید (پیام فارسی روشن) |
| گارد الگو | کلیدهای «بوی توسعه» (شامل `Development-Secret` و…) در تولید رد می‌شوند |
| Rate Limit | اندپوینت‌های عمومی لایسنس سقف ۲۰ درخواست/دقیقه از هر IP گرفتند |

> ⚠️ **نکتهٔ مهم تاریخچه:** کلید قدیمی در تاریخچهٔ گیت باقی است؛ به همین دلیل
> **چرخش کلید روی سرور تولید الزامی است** (بخش ۴ و ۵ همین راهنما).
> صرفِ آپدیتِ فایل‌ها بدون اعمال کلید جدید روی سرور = سرور بالا نمی‌آید (عمدی، برای ایمنی شما).

## ۳. 🧑‍💻 محیط توسعه (User-Secrets)

در **ماشین‌های توسعه** کلید هرگز وارد `appsettings.json` نمی‌شود؛ در Secret Manager نگه داشته می‌شود
(خارج از مخزن، در پروفایل کاربر):

```bash
cd src/Sahand.ClinicPro.API
dotnet user-secrets init
dotnet user-secrets set "Jwt:SecretKey" "<کلید تولیدی بخش ۲>"
```

| نکته | توضیح |
|:---|:---|
| کلید خالی در توسعه؟ | بدون مشکل — گارد در محیط `Development` از کلید جایگزین داخلی استفاده می‌کند و برنامه بالا می‌آید |
| `ASPNETCORE_ENVIRONMENT` | هنگام اجرا از ویژوال استودیو خودش `Development` است؛ نیازی به کار اضافه نیست |
| ماندگاری | User-Secrets در `%APPDATA%\Microsoft\UserSecrets\` ذخیره می‌شود — با هر اجرای بعدی همسان است |

## ۴. 🏥 محیط تولید سرور درمانگاه

### ۴.۱ روش استاندارد — متغیر محیطی `Jwt__SecretKey`

> نام دقیق دقت شود: `Jwt__SecretKey` (دو خط زیر `_ _`) — به بخش `Jwt:SecretKey` نگاشت می‌شود.

| سناریوی اجرای سرور | دستور/محل تنظیم |
|:---|:---|
| **کنسول/ bat فایل** (cmd) | `set Jwt__SecretKey=<کلید>` قبل از اجرای `dotnet Sahand.ClinicPro.API.dll` |
| **PowerShell** | `$env:Jwt__SecretKey="<کلید>"` سپس اجرای برنامه |
| **سرویس ویندوز (sc.exe)** | `sc config <نام‌سرویس> env= Jwt__SecretKey="<کلید>"` یا از رجیستری `HKLM\SYSTEM\CurrentControlSet\Services\<نام>\Environment` |
| **ماندگار برای کل کاربر** | `setx Jwt__SecretKey "<کلید>"` (پس از آن سرویس/پروسه را ری‌استارت کنید) |
| **IIS** | بخش `environmentVariables` در `web.config` یا از «Configuration Editor → environmentVariables» |

<details>
<summary>📦 نمونهٔ کامل web.config برای IIS</summary>

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <location path="." inheritInChildApplications="false">
    <system.webServer>
      <handlers>
        <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
      </handlers>
      <aspNetCore processPath="dotnet" arguments=".\Sahand.ClinicPro.API.dll" stdoutLogEnabled="false" >
        <environmentVariables>
          <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
          <environmentVariable name="Jwt__SecretKey" value="کلید-تولیدی-بخش-۲-اینجا" />
        </environmentVariables>
      </aspNetCore>
    </system.webServer>
  </location>
</configuration>
```

</details>

## ۵. 🔄 چرخش کلید (هر ۶ تا ۱۲ ماه)

| گام | عمل |
|:--:|:---|
| ۱ | کلید جدید تصادفی بسازید (بخش ۲) |
| ۲ | در ساعتی کم‌بار (مثلاً ۱۲ شب) سرور را متوقف کنید |
| ۳ | متغیر `Jwt__SecretKey` را با کلید جدید به‌روز کنید |
| ۴ | سرور را روشن کنید — همهٔ توکن‌های قبلی نامعتبر می‌شوند |
| ۵ | کاربران فعال دسکتاپ پیام «توکن منقضی» می‌بینند و با یک ورود مجدد ادامه می‌دهند |

> 🧊 **مدارک آتی:** اگر قطعی ورود کاربران در چرخش پذیرفتنی نبود، الگوی
> «PreviousKey هم‌اعتبار تا ۲۴ ساعت» در چرخه‌های آتی (S-02 سند مادر) قابل افزودن است؛
> فعلاً سادگی و شفافیت ترجیح داده شد.

## ۶. 🔍 عیب‌یابی — پیام‌های دقیق گارد

سه پیام ممکن است سرور را متوقف کند؛ هرکدام معنای روشنی دارد:

| پیام در لاگ | معنا | راه‌حل |
|:---|:---|:---|
| `⛔ کلید امضای JWT تنظیم نشده است (Jwt:SecretKey)...` | متغیر `Jwt__SecretKey` روی سرور ست نشده | بخش ۴.۱ را دقیق اجرا کنید (دو خط زیر!) |
| `⛔ کلید امضای JWT کوتاه‌تر از ۳۲ بایت است...` | کلید ست شده اما کوتاه است | کلید ۶۴+ کاراکتری از بخش ۲ بگذارید |
| `⛔ کلید امضای JWT دارای الگوی ناامن تشخیص داده شد...` | کلید شامل عبارت‌های توسعه است (`Development-Secret` و…) | کلید تصادفی خالص بگذارید |

نکات سریع:

- **سرور بعد از `setx` بالا نیامد؟** — `setx` فقط برای پروسه‌های آینده است؛ سرور را کاملاً ببندید و دوباره باز کنید.
- **پیام نمی‌بینید ولی 401 می‌گیرید؟** — کلید سرور با کلیدی که توکن ساخته، یکی نیست (چرخش نصفه‌کاره).
- **در توسعه گارد می‌گذارد؟** — `ASPNETCORE_ENVIRONMENT=Development` نبود؛ از ویژوال استودیو اجرا کنید یا متغیر را ست کنید.

## ۷. 📋 پیوست: مرور کامل ۱۲ اندپوینت AllowAnonymous

مرور چرخهٔ ۴۹ — همهٔ نقاط عمومی API با دلیل و کنترل جبرانی:

| # | اندپوینت | دلیل عمومی بودن | ریسک | 🛡 کنترل جبرانی |
|:--:|:---|:---|:---|:---|
| ۱ | `POST /api/v1/auth/login` | نقطهٔ ورود — توکنی برای احراز وجود ندارد | 🟠 brute-force | Rate limit `auth` (۵/دقیقه) + قفل ۳۰ دقیقه‌ای بعد از ۵ خطا |
| ۲ | `POST /api/v1/auth/refresh` | تمدید توکن با refresh token خودِ بدنه | 🟡 بازپخش توکن | عمر ۷ روز + چرخش توکن در هر تمدید + ثبت IP |
| ۳ | `POST /api/v1/auth/logout` | ابطال refresh token — نیازمند احراز نیست چون خود توکن در بدنه است | 🟢 کم | ابطال فقط توکنِ خودِ فراخواننده |
| ۴ | `GET /api/v1/license/status` | پنجرهٔ فعال‌سازی دسکتاپ پیش از ورود باید وضعیت را ببیند | 🟢 کم | فقط کلید/انقضا/ماژول‌ها — دادهٔ بالینی ندارد |
| ۵ | `GET /api/v1/license/support` | اطلاعات تماس پشتیبانی برای کاربرِ قفل‌شده | 🟢 کم | عمومی‌بودن اطلاعات پشتیبانی عمدی است |
| ۶ | `GET /api/v1/license/settings` | پنجرهٔ فعال‌سازی باید نشانی سرور لایسنس را نشان دهد | 🟢 کم | فقط خواندن یک URL |
| ۷ | `PUT /api/v1/license/settings` | تغییر نشانی سرور لایسنس از پنجرهٔ فعال‌سازی | 🔴 تغییر نشانی به سرور مهاجم | **Rate limit `license` (۲۰/دقیقه)** از چرخهٔ ۴۹ + اعتبارسنجی http/https |
| ۸ | `GET /api/v1/license/activation-request` | ساخت فایل درخواست آفلاین پیش از ورود | 🟢 کم | خروجی فقط شامل اثر انگشت سخت‌افزاری است |
| ۹ | `POST /api/v1/license/activate` | فعال‌سازی برخط — پیش از وجود هر توکنی | 🟠 تلاش‌های تصادفی کلید | Rate limit `license` (۲۰/دقیقه) |
| ۱۰ | `POST /api/v1/license/activate-offline` | فعال‌سازی برون‌خط از فایل lic | 🟡 تزریق فایل جعلی | امضای RSA سرور لایسنس روی فایل lic لازم است |
| ۱۱ | `POST /api/v1/license/refresh` | تپ قلب لایسنس — حتی پنجرهٔ فعال‌سازی صدا می‌زند | 🟢 کم | Rate limit `license` (۲۰/دقیقه) |
| ۱۲ | `GET /health` | نقطهٔ بررسی سلامت برای مانیتورینگ و کلاینت | 🟢 کم | فقط وضعیت — `ExcludeFromDescription` |

**جمع‌بندی مرور:** هر ۱۲ مورد «عمومی‌بودنِ موجه» دارند (چرخهٔ ورود، فعال‌سازی لایسنس و سلامت).
تنها ریسک قرمز (ردیف ۷) از این چرخه با سقف نرخ ۲۰/دقیقه مهار شد؛ ردیف‌های نارنجی با
قفل حساب/نرخ لایسنس پوشش داده شده‌اند. **فهرست کامل را در هر تغییر کنترلر هم‌زمان به‌روز کنید.**
