۱️⃣ این راهنما برای چیست؟

برنامه درمانگاه سهند از سه لایه ساخته شده که هرکدام کار خودش را انجام می‌دهند. اولین لایه SQL Server است؛ دفترچه مرکزی درمانگاه که همه اطلاعات بیمارها، نوبت‌ها، فاکتورها و داروها در آن نوشته می‌شود. دومین لایه سرور برنامه (API) است؛ مثل یک منشی که بین برنامه و دفترچه وساطت می‌کند و مطمئن می‌شود هیچ‌کس بدون اجازه چیزی نخواند یا ننویسد. لایه سوم خود نرم‌افزار دسکتاپ است؛ پنجره‌ای که کاربران با آن کار می‌کنند و در راهنمای کاربر با آن آشنا می‌شوید.

این راهنما دقیقاً یک هدف دارد: وصل‌کردن برنامه به SQL Server و ساختن دیتابیس در اولین نصب و اجرا. یعنی در انتهای این راهنما، دیتابیسی به نام SahandClinicProDb با حدود ۹۴ جدول آماده کار است، سرور برنامه روشن است و شما با نام کاربری اولیه وارد برنامه شده‌اید. از این به بعد هر بار برنامه را باز کنید، همه‌چیز همین‌طور آماده است و دیگر لازم نیست هیچ‌کدام از این قدم‌ها را تکرار کنید.

👀 چه انتظاری داشته باشید: هیچ دستور سنگین یا متن پیچیده‌ای در کار نیست. هر جا باید چیزی تایپ کنید، همان را داخل کادر تیره‌رنگ آورده‌ایم تا فقط کپی کنید و بچسبانید. اگر جایی چیزی آن‌طور که نوشته‌ایم نشد، اصلاً نگران نباشید — دو جدول رفع اشکال انتهای راهنما تقریباً همه موقعیت‌های رایج را پوشش می‌دهند.
💡 سه راهنمای خواهر این راهنما: برای نصب ویژوال استودیو و باز کردن پروژه، «راهنمای دانلود پروژه و خروجی گرفتن» (VS-Guide) را ببینید. برای نصب کامل روی شبکه درمانگاه با چند رایانه، «راهنمای قدم‌به‌قدم نصب و راه‌اندازی» (Install-Guide) را ببینید. برای کار با خود برنامه هم «راهنمای کاربر» (User-Guide) آماده است. این چهار فایل هم‌راه هم، کل مسیر از صفر تا استفاده روزمره را پوشش می‌دهند.

۲️⃣ قبل از شروع — سه نکته مهم و پیش‌نیازها

۱) ترتیب قدم‌ها مهم است: اول SQL Server را نصب می‌کنیم، بعد نام آن را پیدا می‌کنیم، بعد برنامه را با آن آشنا می‌کنیم، بعد دیتابیس را می‌سازیم و در آخر سرور و برنامه را اجرا می‌کنیم. اگر جا بپرید یا ترتیب را به‌هم بریزید، برنامه پیام خطا می‌دهد — اما همین راهنما دارد و جدول رفع اشکال پایین هم هست؛ چیزی از دست نمی‌رود.

۲) همه‌چیز رایگان است: نسخه SQL Server 2022 Express که در این راهنما نصب می‌کنیم، نسخه رایگان مایکروسافت است و برای درمانگاه‌های کوچک و متوسط کاملاً کافی است. نه هزینه نرم‌افزاری دارد و نه لایسنس جداگانه می‌خواهد.

۳) هیچ‌چیز خراب نمی‌شود: دستوری که در قدم ۵ اجرا می‌کنید فقط می‌سازد؛ چیزی را حذف یا پاک نمی‌کند. اجرای دوباره آن هم بی‌خطر است؛ برنامه هوشمندانه می‌فهمد چه جدول‌هایی از قبل ساخته شده و فقط بقیه را می‌سازد.

⚠️ فقط یک استثنا: اگر روی این رایانه قبلاً نسخه قدیمی‌تری از برنامه درمانگاه نصب بوده و اطلاعات واقعی بیمار در آن ثبت شده، قبل از اجرای قدم ۵ با پشتیبانی تماس بگیرید تا ابتدا از دیتابیس قدیمی نسخه پشتیبان تهیه شود. برای نصب نو روی رایانه جدید، هیچ نگرانی‌ای نیست.

۳️⃣ قدم ۱: نصب SQL Server 2022 Express

SQL Server را فقط روی رایانه‌ای نصب کنید که قرار است «سرور» درمانگاه باشد. اگر فقط یک رایانه دارید، همان رایانه خودتان سرور است و هیچ مشکلی هم نیست. روی رایانه‌های کاربران (پذیرش و اتاق‌ها) SQL نصب نکنید.

۱

در مرورگر (Chrome یا Edge) این نشانی را باز کنید و دکمه Download now را بزنید:

https://www.microsoft.com/en-us/download/details.aspx?id=104781
(اگر باز نشد، در گوگل جستجو کنید: SQL Server 2022 Express download)
۲

فایل دانلودشده معمولاً به نام SQLServer2022-SSEI-Expr.exe است. روی آن دوبار کلیک کنید. اگر پنجره «User Account Control» پرسید اجازه تغییر بدهم؟، روی Yes کلیک کنید.

👀 چه انتظاری داشته باشید: یک پنجره کوچک باز می‌شود با سه گزینه: Basic / Custom / Download Media. گزینه Basic (پیش‌فرض) همان چیزی است که می‌خواهیم — ساده‌ترین نصب با تنظیمات پیشنهادی مایکروسافت.
۳

روی Accept و بعد Install کلیک کنید و صبر کنید. در این مرحله چند چای بخورید ☕ — نصب ۵ تا ۱۵ دقیقه طول می‌کشد و نوار پیشرفت خودش جلو می‌رود.

۴

وقتی نصب تمام شد، صفحه‌ای مثل تصویر زیر می‌بینید. این صفحه یک نکته طلایی دارد: در بخش Connection string جلوی Data Source= نوشته شده است. این همان «نشانی» SQL شماست — معمولاً localhost\SQLEXPRESS. آن را یادداشت کنید (یا از همین صفحه عکس بگیرید)؛ در قدم ۲ و ۴ به آن نیاز داریم.

صفحه پایان نصب — مقدار جلوی Data Source را یادداشت کنید؛ نام نمونه شماست
⚠️ مهم: اگر وسط نصب پیام «Restart is required» (نیاز به راه‌اندازی مجدد) دیدید، رایانه را Restart کنید و بعد از بالا آمدن، دوباره فایل نصب را اجرا کنید تا مرحله نهایی را کامل کند — بقیه قدم‌های این راهنما از همین‌جا ادامه می‌یابد.
💡 حالت پیشنهادی برای متخصص‌ها: اگر می‌خواهید نام نمونه نداشته باشید و نشانی کوتاه localhost بماند، هنگام نصب به‌جای Basic گزینه Custom را بزنید و در مرحله Database Engine Configuration نوع نصب Default instance را انتخاب کنید. برای بقیه ما، همان Basic با نام SQLEXPRESS کاملاً مناسب است.

۴️⃣ قدم ۲: نام نمونه (Instance) خود را پیدا کنید

هر SQL Server هنگام نصب یک «نام نمونه» می‌گیرد — مثل شماره اتاق در یک ساختمان. بیشترین خطاهایی که کاربران تازه‌کار می‌بینند به‌خاطر اشتباه در همین نام است؛ پس این قدم کوتاه را با دقت انجام دهید تا بقیه راه هموار باشد.

اگر در قدم ۱ مقدار جلوی Data Source= را یادداشت کرده‌اید، همین حالا آن را دارید و کافی است. اگر نه، ساده‌ترین راه این است:

۱

از منوی Start تایپ کنید services.msc و Enter بزنید. پنجره Services باز می‌شود.

۲

در فهرست، سرویسی پیدا کنید که نامش با SQL Server شروع می‌شود و کنارش داخل پرانتز یک نام دارد — مثلاً SQL Server (SQLEXPRESS). همان نام داخل پرانتز، نام نمونه شماست.

۳

مطمئن شوید «Status» این سرویس Running است. اگر نبود، روی آن راست‌کلیک و Start بزنید.

حالا بسته به آنچه دیدید، «نشانی SQL شما» یکی از این دو حالت است:

نام سرویس در پنجره Servicesیعنی چه؟در رشته اتصال چه بنویسیم؟ (قدم ۴)
SQL Server (SQLEXPRESS)نصب Express با نام پیش‌فرض — رایج‌ترین حالتlocalhost\SQLEXPRESS
SQL Server (MSSQLSERVER)نمونه بی‌نام (Default instance)فقط localhost
👀 چه انتظاری داشته باشید: اگر چند سرویس «SQL Server (...)» دیدید (مثلاً نسخه قدیمی ۲۰۰۸ یا ۲۰۱۹ کنار ۲۰۲۲)، جدی‌ترین راه تشخیص این است که به صفحه پایان نصب قدم ۱ نگاه کنید؛ همان مقدار Data Source مال نصب تازه شماست. برای اطمینان می‌توانید نسخه هر نمونه را هم ببینید: روی سرویس راست‌کلیک ← Properties ← برگه Details ← ببینید «Product version» با چه عددی شروع می‌شود: 16 یعنی ۲۰۲۲ ✓، 15 یعنی ۲۰۱۹، 14 یعنی ۲۰۱۷، 13 یعنی ۲۰۱۶، 11 یعنی ۲۰۱۲ و 10 یعنی ۲۰۰۸/۲۰۰۸R2. اگر نمونه‌ای قدیمی‌تر از ۱۶ دیدید، آن مال نرم‌افزارهای قدیمی نصب‌شده روی ویندوزتان است و به هیچ وجه نباید در قدم ۴ بنویسیدش — این برنامه به نسخه ۲۰۲۲ نیاز دارد (جدول رفع اشکال ۱، ردیف SEQUENCE را ببینید). راهنمای نصب کامل چند-نمونه‌ای در بخش حالت‌های پیشرفته آمده است.

۵️⃣ قدم ۳: نصب SSMS و تست سلامت SQL (اختیاری ولی توصیه‌شده)

SSMS (SQL Server Management Studio) برنامه رایگان مایکروسافت برای «دیدن داخل» SQL Server است — مثل پنجره‌ای به دفترچه مرکزی. با آن می‌توانید مطمئن شوید SQL سالم است و بعداً در قدم ۵ ساخته‌شدن جدول‌ها را با چشم خودتان ببینید.

۱

از نشانی کوتاه مایکروسافت دانلودش کنید (یا در گوگل جستجو کنید: SSMS download):

https://aka.ms/ssmsfullsetup
۲

نصب‌کننده را اجرا کنید (اگر اجازه خواست، Yes)، روی Install کلیک کنید و تا پایان صبر کنید؛ ممکن است چند دقیقه طول بکشد و در پایان بخواهد رایانه Restart شود — انجام دهید.

۳

SSMS را از منوی Start باز کنید. در پنجره Connect to Server این مقادیر را بگذارید:

فیلدچه بنویسیم؟
Server nameنشانی SQL از قدم ۲ — مثلاً localhost\SQLEXPRESS
AuthenticationWindows Authentication (پیش‌فرض)
User name / Passwordخالی می‌ماند — ویندوز خودش شما را می‌شناسد

و روی Connect کلیک کنید.

👀 چه انتظاری داشته باشید: اگر پنجره اصلی SSMS باز شد و در گوشه چپ بالای آن (بخش Object Explorer) عبارت سبز «connected» را دیدید، تبریک — SQL شما کاملاً سالم است. اگر پیام خطا آمد، قبل از ادامه، جدول رفع اشکال ۱ (انتهای راهنما) را ببینید؛ تقریباً همیشه مشکل از نام نمونه است.
💡 این قدم را دور نریزید: حتی اگر الان تندرست هستید، SSMS در قدم ۵ برای دیدن جدول‌های ساخته‌شده و در آینده برای کارهای پشتیبانی (مثل تهیه نسخه پشتیبان) به‌دردتان می‌خورد.

۶️⃣ قدم ۴: معرفی برنامه به SQL (فایل appsettings.json)

برنامه نمی‌تواند حدس بزند SQL شما کجاست و چه نامی دارد؛ باید به آن بگوییم. این آشنایی در فایلی به نام appsettings.json داخل پروژه سرور برنامه (API) انجام می‌شود. فقط یک خط از این فایل برای ما مهم است: خطی که با DefaultConnection شروع می‌شود — همان «رشته اتصال».

۱

در ویژوال استودیو، پنجره Solution Explorer (سمت راست) را باز کنید؛ پروژه Sahand.ClinicPro.API را پیدا کنید و آن را باز کنید تا فایل‌هایش دیده شوند. روی فایل appsettings.json دوبار کلیک کنید تا باز شود.

۲

خط DefaultConnection را پیدا کنید (بالاهای فایل، داخل بخش ConnectionStrings). حالا بسته به حالت شما یکی از این دو نمونه را جایگزین مقدار فعلی کنید:

حالت الف — نمونه بی‌نام (نصب Custom با Default instance، یا SQL از قبل موجود روی همین رایانه):

"DefaultConnection": "Server=localhost;Database=SahandClinicProDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"

حالت ب — نمونه نام‌دار SQLEXPRESS (نصب Basic — رایج‌ترین حالت):

"DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=SahandClinicProDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
⚠️ نکته بسیار مهم — دو خط اریب: در فایل‌های JSON برای نوشتن یک \ باید دو تا \\ پشت‌سرهم بنویسید (همان‌طور که در حالت ب می‌بینید). اگر فقط یکی بگذارید، فایل خراب می‌شود و سرور با پیام خطای JSON بالا نمی‌آید. عیناً از همین کادرها کپی کنید تا این مشکل هرگز برایتان پیش نیاید.
۳

با Ctrl+S ذخیره کنید. تمام! بقیه فایل دست نخورده بماند.

💡 ویرایش کنید، از نو ننویسید: فایل appsettings.json از قبل خط کامل رشته اتصال را دارد؛ شما فقط بخش Server=... همان خط را عوض می‌کنید. رشته‌های کامل داخل این راهنما فقط برای مقایسه و مرجع‌اند — اگر موقع کپی از PDF در چند خط شکسته شدند، در فایل باید در یک خط قرار بگیرند؛ پس به‌جای کپی، همان خط موجود فایل را ویرایش کنید.

🔍 اجزای رشته اتصال به زبان ساده

قطعهیعنی چه؟
Server=localhost\SQLEXPRESSنشانی و نام نمونه SQL — همان که در قدم ۲ پیدا کردید.
Database=SahandClinicProDbنام دیتابیسی که برنامه می‌سازد و استفاده می‌کند؛ آن را عوض نکنید.
Trusted_Connection=Trueورود با حساب ویندوز خودتان (بدون رمز SQL) — ساده‌ترین و امن‌ترین روش برای تک‌رایانه.
User Id=... ; Password=...فقط در حالت «احراز هویت SQL» — به بخش حالت‌های پیشرفته (الف) مراجعه کنید.
TrustServerCertificate=Trueاجازه اتصال با گواهی پیش‌فرض خود SQL — بدون این عبارت، ویندوز اتصال را به‌خاطر «اعتماد نداشتن به گواهی» قطع می‌کند.
MultipleActiveResultSets=trueاجازه می‌دهد برنامه هم‌زمان چند بسته اطلاعات از دیتابیس بخواند — برای سرعت بیشتر.
💡 حافظه تازه‌سازی: سرور برنامه تنظیمات را فقط موقع روشن‌شدن می‌خواند. اگر API همین حالا در حال اجراست، آن را Stop کنید تا در قدم ۶ با تنظیم تازه بالا بیاید.

۷️⃣ قدم ۵: ساخت دیتابیس و همه جدول‌ها با یک دستور

درون پروژه، سازندگان برنامه «مهاجرت‌ها» (Migrations) را از قبل نوشته‌اند؛ یعنی نقشه‌های کامل ساخت حدود ۹۴ جدول — از پرونده بیمار تا نسخه و فاکتور. ما فقط باید یک دستور اجرا کنیم تا برنامه نقشه‌ها را به SQL بدهد و همه‌چیز ساخته شود. این دستور حتی خودِ دیتابیس SahandClinicProDb را هم اگر نباشد، می‌سازد.

۱

در ویژوال استودیو از منوی بالا بروید به: Tools ← Command Line ← Developer PowerShell. یک پنجره سیاه کوچک پایین صفحه باز می‌شود که دستورهای آن شناخته می‌شوند.

۲

ابتدا وارد پوشه پروژه سرور (API) شوید — پوشه‌ای که فایل Sahand.ClinicPro.API.csproj در آن است. اگر پوشه پروژه را در مسیر پیش‌فرض باز کرده‌اید، این دستور همین کار را می‌کند (اگر مسیر شما فرق دارد، جایگزینش کنید):

cd D:\SahandClinicPro\src\Sahand.ClinicPro.API
۳

بار اول فقط، ابزار ساخت دیتابیس را بازیابی کنید (یک‌بار برای همیشه — دفعه بعد این مرحله را ندارید). سازندگان برنامه نسخه درستِ این ابزار را از قبل داخل خودِ فایل‌های پروژه گنجانده‌اند؛ دستور زیر همان نسخه را از اینترنت برداشته و همین‌جا آماده می‌کند (حدود یک دقیقه):

dotnet tool restore

چند خط نوشته ظاهر می‌شود و آرام می‌گیرد؛ تا کلمه error در قرمز ندیدید، یعنی آماده است و می‌توانید بروید سراغ مرحله بعد.

۴

حالا دستور اصلی ساخت دیتابیس را اجرا کنید — عیناً همین یک خط را کپی کنید و Enter بزنید:

dotnet ef database update -p ../Sahand.ClinicPro.Infrastructure -s .

در این دستور، -p یعنی «پروژه دیتابیس»، -s یعنی «پروژه راه‌انداز» و نقطه در انتها یعنی «همین پوشه فعلی» — چون در پوشه API هستید، همین کافی است.

👀 چه انتظاری داشته باشید: اول چند لحظه «Build started» می‌نویسد، بعد خط‌های زرد مانند Applying migration '20261004205244_InitialCreate'. یکی‌یکی رد می‌شوند و در پایان کلمه Done. را می‌بینید. اولین بار ۱ تا ۳ دقیقه طول می‌کشد. همین «Done» یعنی: دیتابیس ساخته شد و همه جدول‌ها آماده‌اند. 🎉
💡 دو نوشته که نگران‌تان نکند: (۱) اگر خط زرد «The Entity Framework tools version ... is older than that of the runtime ...» را دیدید، فقط یادآوری است نه خطا. (۲) اگر وسط کار جمله «خطای مهلک در راه‌اندازی API» همراه واژه HostAbortedException چاپ شد، آن هم اشکال نیست — ابزار ساخت دیتابیس برای برداشتن تنظیمات، سرور را برای یک لحظه روشن و سپس عمداً خاموش می‌کند و خود برنامه این توقف عمدی را به‌اشتباه «خطای مهلک» می‌نامد. خطای «واقعی» فقط پیامی است که با شماره Error Number تمام می‌شود — همان‌ها که ردیف‌های جدول رفع اشکال ۱ را می‌سازند.
💡 دستور بی‌خطر است: اگر یک‌بار دیگر هم اجرایش کنید، چیزی را دوباره نمی‌سازد یا خراب نمی‌کند؛ فقط می‌گوید همه مهاجرت‌ها از قبل اجرا شده‌اند. پس هر وقت شک کردید، دوباره بزنید.

🔍 تأیید با چشم خودتان (با SSMS)

۱

در SSMS روی شاخه Databases راست‌کلیک و Refresh بزنید. حالا دیتابیس SahandClinicProDb را در فهرست می‌بینید.

۲

روی مثلث کنار آن بزنید: Tables ← — فهرستی بلند از جدول‌ها (حدود ۹۴ مورد) را می‌بینید، از Patients و Appointments گرفته تا جدول تاریخچه‌ای به نام __EFMigrationsHistory که ثبت نقشه‌های اجراشده را نگه می‌دارد.

⚠️ نکته کاربر ویندوز: دستور این قدم باید با همان حساب ویندوزی اجرا شود که SQL را نصب کرده است (نصب Express آن حساب را به‌عنوان مدیر SQL ثبت می‌کند). اگر با حساب دیگری می‌زنید و خطای Login failed گرفتید، جدول رفع اشکال ۱ ردیف دوم را ببینید.

۸️⃣ قدم ۶: اولین اجرای سرور برنامه (API)

حالا که انبار آماده است، سرور برنامه را روشن می‌کنیم. سرور (API) همان منشی وساطت‌گر است که برنامه دسکتاپ از طریق آن با دیتابیس حرف می‌زند.

۱

در Solution Explorer روی پروژه Sahand.ClinicPro.API راست‌کلیک کنید: Debug ← Start new instance. (راهنمای VS همین کار را برای پروژه دسکتاپ هم توضیح داده — هر دو می‌توانند هم‌زمان اجرا باشند.)

۲

یک پنجره کنسول باز می‌شود و چند خط نوشته ظاهر می‌شود. دنبال این جمله بگردید:

Now listening on: http://localhost:5000

دیدید این جمله را؟ یعنی سرور با موفقیت روشن شد. اگر به جای عدد 5000 عدد دیگری دیدید (مثلا 2127) هنوز نگران نباشید — جعبه «اگر پورت 5000 نبود» کمی پایین‌تر در همین قدم را ببینید. در همین لحظات اول، سرور چند «بذرافشان» را هم خودکار اجرا می‌کند: نقش‌ها و دسترسی‌ها را می‌سازد، کاربر مدیر اولیه را ثبت می‌کند و داده‌های پایه برنامه را آماده می‌کند — پس چند ثانیه صبر کنید تا خطوط لاگ آرام بگیرند.

کنسول سرور برنامه — نوشتن Now listening یعنی سرور آماده است
⚠️ این پنجره را باز نگه دارید: پنجره کنسول یعنی خود سرور؛ اگر آن را ببندید، سرور خاموش می‌شود و برنامه «اتصال به سرور برقرار نشد» می‌گوید. در حالت توسعه همین‌طور باز می‌ماند؛ برای راه‌اندازی دائمی روی درمانگاه، راهنمای نصب روش سرویس خودکار ویندوز را دارد.
💡 تست سریع سلامت: در مرورگر نشانی http://localhost:5000/health را باز کنید — باید پیام سبز «سامانه درمانگاه سهند فعال است» ببینید. این همان نقطه‌ای است که خود برنامه هم سلامت سرور را با آن می‌سنجد.
💡 مرورگر خودش صفحه‌ای با 404 باز کرد؟ طبیعی است: این برنامه «سرور» است، نه وب‌سایت؛ صفحه خانگی ندارد و نشانی خالی آن (همان / در انتهای آدرس) همیشه 404 می‌دهد. خودِ گرفتن 404 یعنی سرور زنده است و جواب می‌دهد — اگر سرور خاموش بود، مرورگر به جای 404 پیام «اتصال ممکن نیست» می‌داد. برای دیدن زنده بودن سرور همین دو نشانی کافی است: /health (همان تست سلامت بالا) و /swagger (فهرست تصویری همه امکانات سرور — مستندات زنده API؛ فقط وقتی از ویژوال استودیو اجرا شده فعال است).
⚠️ اگر پورت 5000 نبود (مثلا https://localhost:2127): در نسخه ۲.۰.۱ سورس، فایل تنظیم پورت سرور به‌اشتباه از بسته سورس جا افتاده و ویژوال استودیو هر بار پورت تصادفی خودش را می‌سازد. دو اثر دارد: (۱) برای باز کردن health یا swagger باید همان پورتِ خودتان را بگذارید (مثل https://localhost:2127/swagger)؛ (۲) مهم‌تر: برنامه دسکتاپ به نشانی ثابت http://localhost:5000/api/v1 وصل می‌شود و تا سرور روی 5000 نباشد، «اتصال به سرور برقرار نشد» می‌گوید. راه حل یک‌بار برای همیشه: در مسیر src/Sahand.ClinicPro.API/Properties (پوشه Properties را اگر نبود، در همان پوشه پروژه API بسازید) فایلی به نام launchSettings.json بسازید، این متن را داخلش بگذارید و ذخیره کنید؛ بعد پنجره سرور را ببندید و سرور را دوباره اجرا کنید — از این به بعد همیشه روی 5000 بالا می‌آید و مرورگر هم مستقیم صفحه swagger را باز می‌کند (در نسخه ۲.۰.۲ به بعد همین فایل خودش داخل سورس است و این کار لازم نیست): 
{
  "profiles": {
    "http": {
      "commandName": "Project",
      "launchBrowser": true,
      "launchUrl": "swagger",
      "applicationUrl": "http://localhost:5000",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    }
  }
}
💡 چهار نوشته که در پنجره سرور نگران‌تان نکند: (۱) به جای جمله‌های فارسی فقط علامت سؤال (؟؟؟؟) می‌بینید — مشکل نمایشی کنسول ویندوز با حروف فارسی و ایموجی است؛ متن واقعی همان جمله‌های فارسی است، مثلا «بذرافشان AdminSeeder با موفقیت اجرا شد». (۲) سه خط زرد با عبارت global query filter (درباره User و Role و Permission) — یادآوری فنی الگوی «حذف نرم» داده‌هاست؛ بی‌خطر. (۳) خط زرد No store type ... DefaultCoveragePercent — درباره دقت اعشاری ستون «درصد پوشش بیمه» است؛ مقادیر درصد (۰ تا ۱۰۰) در ستون پیش‌فرض کاملاً جا می‌شوند؛ بی‌خطر. (۴) اگر خط زرد Failed to determine the https port را دیدید — یعنی سرور فقط روی http بالا است و هدایت خودکار به https انجام نمی‌شود؛ برای همین برنامه کاملاً درست است. هیچ‌کدام از این چهار مورد خطا نیستند و سرور با تمام توان کار می‌کند.

1️⃣2️⃣ حالت‌های خاص و پیشرفته (اختیاری)

این بخش برای موقعیت‌های خاص است؛ اگر مسیر اصلی این راهنما را رفته‌اید، به هیچ‌کدام از این‌ها نیازی ندارید و می‌توانید مستقیم به چک‌لیست نهایی بروید.

🔑 الف) اتصال با کاربر و رمز SQL (به‌جای حساب ویندوز)

گاهی برنامه باید با یک کاربر رمزدار به SQL وصل شود — مثلاً وقتی ویندوز درمانگاه دامین دارد یا نصب‌کننده SQL و کاربر روزمره یکی نیستند. برای این کار باید هنگام نصب SQL گزینه Custom را انتخاب کنید و در مرحله «Database Engine Configuration» حالت احراز هویت را روی Mixed Mode بگذارید و برای کاربر sa یک رمز قوی تعیین کنید (حروف بزرگ و کوچک + عدد + علامت، حداقل ۸ کاراکتر — ویندوز اجازه رمز ساده نمی‌دهد). آن‌وقت رشته اتصال چنین شکلی می‌گیرد:

"DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=SahandClinicProDb;User Id=sa;Password=رمز-شما;TrustServerCertificate=True;MultipleActiveResultSets=true"
💡 پیشنهاد ما: برای تک‌رایانه و شبکه کوچک، همان روش پیش‌فرض این راهنما (ورود با حساب ویندوز) هم ساده‌تر است و هم امن‌تر — چون رمزی وجود ندارد که فراموش یا لو برود. Mixed Mode را فقط وقتی انتخاب کنید که دلیل مشخصی دارید.

🖥 ب) چند رایانه در شبکه درمانگاه

منطق کار همان است که یاد گرفتید؛ فقط دو تفاوت کوچک دارد: اولاً SQL و سرور برنامه روی رایانه مرکزی (سرور) می‌مانند و روی رایانه‌های کاربران فقط برنامه دسکتاپ نصب می‌شود. ثانیاً در فایل پیکربندی برنامه هر کلاینت، مقدار BaseUrl به‌جای localhost نشانی IP رایانه سرور می‌شود (مثل http://192.168.1.10:5000/api/v1) و در فایروال سرور پورت‌های ۵۰۰۰ و ۱۴۳۳ باز می‌شوند. تمام این کارها با تصویر و قدم‌به‌قدم در «راهنمای قدم‌به‌قدم نصب و راه‌اندازی» (Install-Guide) آمده است — همین راهنما را به مسئول شبکه بدهید.

📦 ج) راه‌اندازی دائمی بدون ویژوال استودیو (نسخه منتشرشده)

اجرای از ویژوال استودیو برای یادگیری و تست عالی است؛ اما برای کار روزمره درمانگاه، سرور باید بدون برنامه‌نویس روشن بماند. بسته نصب پروژه (پوشه installer مخزن) این را خودکار می‌کند: فایل INSTALL-SERVER.bat روی رایانه سرور، همه‌چیز را منتشر می‌کند، همان دستور ساخت دیتابیس قدم ۵ را اجرا می‌کند و سرور را به‌صورت «سرویس ویندوز» ثبت می‌کند تا با هر روشن‌شدن رایانه خودکار بالا بیاید. برای این حالت فقط دو نکته اضافه دارد: اول اینکه فایل appsettings.json موردنظر دیگر کنار سورس نیست، بلکه کنار فایل‌های منتشرشده سرور است (مثلاً C:\SahandClinicPro\Server\appsettings.json). دوم اینکه در محیط تولید، عوض‌کردن کلید امضای Jwt:SecretKey به یک مقدار تصادفی حداقل ۶۴ کاراکتری الزامی است — راهنمای کامل استقرار (فایل deployment در مخزن) دستور ساخت این کلید را دارد.
