# گزارش متمرکز اصلاحات باقی‌مانده

این گزارش وضعیت شناخته‌شده در شاخهٔ کاری را ثبت می‌کند؛ وجود یک مورد در این فهرست به معنی رفع یا آزمون موفق آن نیست. آخرین مبنای بررسی کد پیش از ایجاد گزارش، کامیت `9d4b67f` است.

## ۱. طرح تأییدشده و طراح چاپ

- [ ] تطبیق پیکسل‌به‌پیکسل صفحهٔ پیاده‌شده با `docs/design/print-template-new-proposal.png` هنوز حاصل یا تأیید نشده است. ساختار و محتوای پنل‌ها و بوم همچنان تفاوت‌های قابل‌مشاهده دارند.
- [ ] مقایسه در حالت‌های مختلف اندازهٔ پنجره، مقیاس ویندوز، فونت، داده و اسکرول انجام شود. `docs/design/compare.html` مقایسهٔ تصویری فراهم می‌کند؛ تصویر هم‌اندازهٔ `docs/screenshots/real/print-designer-layout.png` رندر WPF خارج از صفحه با DPI مقیاس‌شده است و جایگزین تصویر واقعی مانیتور نیست. تصویر واقعی در `docs/screenshots/real/print-designer.png` قرار دارد.
- [ ] کشیدن واقعی ابزار و عنصر، هشت دستگیره، لغو حرکت با Escape یا قطع capture، ترتیب لایه، اسکرول و بزرگ‌نمایی در محیط تعاملی ویندوز آزموده شوند. تست خودکار WPF وجود دستگیره‌ها و اعمال رنگ را بررسی می‌کند، نه کشیدن واقعی ماوس.
- [ ] خروجی دادهٔ واقعی، جدول‌های طولانی، حاشیه، صفحه‌بندی، اندازه و جهت کاغذ و چاپ فیزیکی روی چاپگرهای هدف آزموده شوند. نمایش جدول نمونه روی بوم تقریبی است و محافظ سرریز تضمین صفحه‌بندی یا رفتار درایور نیست.
- [ ] عملکرد همهٔ مسیرهای طراح، ذخیره و بازخوانی قالب‌های موجود، سازگاری داده‌های قدیمی و رفتار لغو تغییرات به‌صورت انتهابه‌انتها بازبینی شود.

## ۲. تنظیمات و جریان چاپ

- [ ] تنظیمات تمام‌عرض، تعداد نسخه‌ها، انتخاب چاپگر و پیش‌نمایش در همهٔ مسیرهای متصل با چاپگر واقعی و حالت انصراف آزموده شوند. در پیش‌نمایش HTML نتیجهٔ نهایی چاپ یا انصراف مرورگر قابل تأیید نیست؛ بسته‌شدن خودکار آن نباید موفقیت چاپ را جعل کند.
- [ ] قبض قدیمی پذیرش، قالب پیش‌فرض آن و خروجی واقعی سایر قالب‌ها با نمونه‌های مورد تأیید و دادهٔ واقعی بررسی شوند.
- [ ] پوشش و کارکرد واقعی میانبرهای قابل‌مشاهدهٔ تمام دکمه‌های ثبت و ذخیره، از جمله موارد تعارض، بررسی شود.

## ۳. فرم‌ها و جریان‌های بالینی و مالی

- [ ] همهٔ فرم‌های بازطراحی‌شده با طرح تأییدشده و عملکرد واقعی خود مقایسه شوند؛ صرف نمایش کنترل‌ها کافی نیست. به‌ویژه تطبیق و عملکرد صفحات دندان‌پزشکی، فیزیوتراپی، چشم‌پزشکی، نظرسنجی، پذیرش و تصویربرداری بازبینی شود؛ یادداشت دندان جای رزرو واقعی را نمی‌گیرد.
- [ ] پذیرش و نوبت جدید با دادهٔ واقعی، پاسخ‌های دیررس، خطا و ریست کامل انتهابه‌انتها آزموده شوند. زنجیرهٔ پذیرش تا پرداخت یک تراکنش اتمی واحد نیست.
- [ ] بازیابی و تکرار امن پرداخت، فاکتور و پذیرش با SQL Server و سناریوهای واقعی قطع ارتباط، چند کاربر، تغییر دستگاه یا حساب و بازیابی پایگاه بررسی شود؛ نگهداری محلی اطلاعات بازیابی هماهنگی بین دستگاه‌ها را تضمین نمی‌کند.
- [ ] حسابداری، حساب پیش‌فرض و نگاشت روش‌های پرداخت، گردکردن و موارد بیمه و مصرفی با قواعد مالی مورد تأیید و دادهٔ واقعی بررسی شوند. در نبود حساب پیش‌فرض امکان ثبت فاکتور یا پرداخت بدون سند حسابداری وجود دارد.
- [ ] مسیرهای نسخه، ویزیت، ارجاع، آزمایش، تصویربرداری و مصرف چند بچ در رقابت SQL و با دادهٔ واقعی بررسی شوند. صحت بالینی داده‌های تصویربرداری و DICOM سفارشی جداگانه نیازمند تأیید است.
- [ ] مسیر عمومی نظرسنجی، رقابت پایگاه داده و ارسال و ارسال مجدد پیامک با زیرساخت واقعی آزموده شوند؛ آزمون‌های SQLite جایگزین SQL Server و سرویس پیامک نیستند.

## ۴. نصب و بازیابی پایگاه داده

- [ ] خطای گزارش‌شدهٔ مجوز بازیابی و تنظیم نقش SQL روی محیط واقعی کاربر، با حساب اتصال واقعی API و حساب دارای مجوز مدیریتی، بررسی شود. موفقیت اسکریپت یا تست‌های ایستا به‌تنهایی موفقیت `RESTORE` را ثابت نمی‌کند.
- [ ] نصب کامل و ارتقا از نسخهٔ موجود، migrationها، حفظ پیکربندی و بارگذاری وابستگی‌های جدید روی ویندوز و SQL Server واقعی آزموده شوند. همچنین روش پشتیبان‌گیری و بازگشت عملی تأیید شود.

## ۵. ساخت، انتشار و مرج

- [ ] ساخت بدون خطا و بدون هشدار، از جمله هشدارهای سرکوب‌شده، جداگانه بررسی شود؛ موفقیت CI به‌تنهایی اثبات صفر هشدار مطلق نیست.
- [ ] پس از تکمیل و تأیید اصلاحات، بسته‌های نصب و به‌روزرسانی جدید مطابق درخواست کاربر ساخته و بررسی شوند؛ سپس مرج و پاک‌سازی شاخه‌های اضافی طبق دستور کاربر انجام شود. این گزارش به‌تنهایی به معنی انجام انتشار یا مرج نیست.
