🎯 اصول SOLID در پروژه

S - Single Responsibility

هر کلاس فقط یک مسئولیت دارد. Service‌ها، Repository‌ها، Controller‌ها هر کدام یک وظیفه مشخص.

O - Open/Closed

سیستم باز برای توسعه (پلاگین SMS Provider جدید) و بسته برای تغییر (Interface‌ها ثابت).

L - Liskov Substitution

کلاس‌های فرزند جایگزین پدر می‌شوند بدون شکستن کد. مثلاً هر SmsProvider قابل جایگزینی.

I - Interface Segregation

Interface‌های کوچک و تخصصی. مثلاً IReadRepository و IWriteRepository.

D - Dependency Inversion

وابستگی به Interface‌ها نه کلاس‌های concrete. DI Container برای Inject.

Design Patterns

Repository, UoW, CQRS, Mediator, Factory, Strategy, Observer, Decorator
