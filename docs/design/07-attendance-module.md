## پروتکل اتصال دستگاه‌ها

### ZKTeco — PULL SDK (TCP/4370)

پیاده‌سازی وفادار به مرجع متن‌باز `pyzk`:

```
پوشش TCP:   [0x5050][0x7282][طول u32 LE]
هدر بسته:  [command u16][checksum u16][session u16][reply u16]
چک‌سام:     جمع u16ها با wrap-around (zkemsdk)
```

| فرمان | کد | شرح |
|-------|-----|-----|
| `CMD_CONNECT` | 1000 | دست‌دادن اتصال — نشست/پاسخ از هدر پاسخ |
| `CMD_EXIT` | 1001 | قطع مؤدبانه |
| `CMD_GET_TIME` | 201 | خواندن زمان دستگاه |
| `CMD_ATTLOG_RRQ` | 13 | درخواست همه رکوردهای حضور |
| `CMD_PREPARE_DATA` | 1500 | پاسخ دستگاه با حجم کل |
| `CMD_DATA` / `CMD_FREE_DATA` | 1501/1502 | جریان داده و تصدیق |
| `CMD_ACK_OK` | 2000 | پاسخ موفق |

**رکورد حضور (۴۰ بایت):**

```
[uid u16][userId 24B ASCII][status u8][epoch u32 LE][punch u8][رزرو 8B]
```

نگاشت وضعیت: `0=ورود 1=خروج 2=خروج استراحت 3=بازگشت 4/5=اضافه‌کاری` — زمان epoch دستگاه (محلی) به UTC ایران تبدیل می‌شود.

### Hikvision — ISAPI (HTTP/Digest)

```
GET /ISAPI/System/deviceInfo?format=json     → سریال و مدل
GET /ISAPI/AccessControl/InOutInfo?format=json → گزارش حوادث
احراز هویت: Digest — کلید ارتباطی به قالب «user:pass»
```

### شبیه‌ساز (Generic)

تولید ضربه‌های منطقی برای دمو و آموزش: ورود ۷:۴۵–۸:۲۰ و خروج ۱۴:۱۰–۱۶:۴۰ برای شناسه‌های ۱ تا ۲۹.

## موتور محاسبات

`AttendanceCalculator` — کلاس خالص و تست‌پذیر با ۱۶ سناریوی تست‌شده:

```
ورودی:  تاریخ + ضربه‌ها (UTC) + شیفت (اختیاری) + مرخصی تأییدشده + تعطیلی
خروجی: ورود/خروج مؤثر، دقایق تأخیر/تعجیل، کارکرد، اضافه‌کاری، وضعیت
```

**قواعد:**

1. **پنجره تطبیق:** از ۴ ساعت پیش از شروع شیفت تا ۶ ساعت پس از پایان
2. **حذف همسازه:** ضربه‌های نزدیک‌تر از `MinMinutesBetweenPunches` (پیش‌فرض ۵ دقیقه) حذف می‌شوند
3. **تأخیر:** `(ورود − شروع) − تحمل` فقط مثبت
4. **تعجیل:** `(پایان − خروج) − تحمل` فقط مثبت
5. **کارکرد:** فاصله مؤثر منهای استراحت، مشروط به سقف طول شیفت
6. **اضافه‌کاری:** تفاوت خروج با `(پایان + آستانه)` — پیش‌فرض آستانه ۱۵ دقیقه
7. **شیفت شب:** پایان پس از نیمه‌شب به روزِ شروع تعلق می‌گیرد
8. **اولویت وضعیت:** مرخصی/مأموریت تأییدشده بدون ضربه > غیبت > تأخیر > حاضر
9. **تعطیل رسمی:** بدون ضربه غایب شمرده نمی‌شود
10. **بدون شیفت:** تجمیع ساده اولین/آخرین ضربه

## جریان همگام‌سازی

```
AttendanceSyncJob (Hangfire - هر دقیقه)
        │  سنجش موعد: LastSyncAt + SyncIntervalMinutes <= اکنون
        ▼
AttendanceSynchronizer.SyncDeviceAsync
        │
        ├─► ۱. درایور متناسب برند از کارخانه
        ├─► ۲. Pull ضربه‌های پس از آخرین سینک (پنجره اولیه ۷ روز)
        ├─► ۳. درج لاگ خام + حذف تکراری با HashSet و ایندکس یکتا
        ├─► ۴. به‌روزرسانی وضعیت دستگاه (متصل/خطا/تعداد لاگ)
        └─► ۵. ProcessPendingLogsAsync:
                ├─ نگاشت (دستگاه، شناسه) → پرسنل — بی‌نگاشت = خطا با پیام
                ├─ گروه‌بندی بر پرسنل و تاریخ محلی ایران
                ├─ یافتن شیفت مؤثر (بیشترین اولویت) + مرخصی + تعطیلی
                ├─ محاسبه با AttendanceCalculator
                └─ Upsert رکورد حضور + علامت‌گذاری لاگ‌ها
```
